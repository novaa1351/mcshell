# The Advancements screen is the filesystem

A directory tree in vanilla's advancement window, kept to the pixel.

Moved out of CLAUDE.md word for word on 2026-10-16, so that file stays
short enough to read in full every session. The reasons below are the
point: read them before changing the thing they describe.

## The Advancements screen is the filesystem
Vanilla's advancement window is already a tree — nodes on a grid, gold frames
for what has been reached, branches drawn between a parent and its children,
all of it panned behind tiled stone. A directory tree is that shape, so the
window is **kept to the pixel** (texture, 252x140 geometry, 26x26 frames, the
two-pass black-then-white connector lines, drag to pan, scroll by 16) and only
the contents are replaced. Vanilla's own screen is **buried**, like Statistics
and Open to LAN: in a void world with mob spawning off it is a list of things
that will never happen.

- **The tree is discovered, not delivered.** An advancement tree arrives whole
  from the server; a filesystem does not. So the home directory starts with
  nothing under it and a click grows a branch. This is the one real departure
  from vanilla's screen and it is forced by the subject.
- **One button opens and closes.** A directory that is shut opens, one that is
  open shuts. There is nothing a second button could add: only an open branch
  can be closed, so the two can never be wanted in the same state, and
  whichever applies is the only thing a click could sensibly mean.
- **Gold means expanded**, grey means not. As close to vanilla's own meaning
  as this gets: gold is the part of the tree you have opened up.
- **The window is grown to the screen, not scaled.** Vanilla's 252x140 shows
  eight columns by four rows, which is not enough to see where you are in a
  filesystem. The frame is nine-sliced — corners drawn whole, the flat bevelled
  edges repeated — so the border, the folders and the text all stay at one
  pixel scale. Scaling the window instead would have been a line and would have
  made the chrome twice the size of its own contents, which is the tell.
- **Files are drawn, and nothing more.** A directory full of documents that
  draws as an empty one is a worse picture than none, so files are listed
  beside the subdirectories with an icon for what they are. They are leaves:
  clicking one does nothing, because nothing here could decide what opening a
  file means — that is the command bar's job, and the catalog's.
- **What a file *is* is the daemon's, what it looks like is the mod's.** The
  extension table lives in `files.py`, where re-tagging a format is one line,
  the way the catalog's categories are. The mod holds one 16x16 texture per
  kind and falls back to a plain page, so an unknown kind cannot draw as
  Minecraft's missing-texture check. The icons are generated by
  `mod/tools/icons.py` rather than kept as opaque PNGs — every one of them is
  the same sheet of paper with a different badge, and a colour is a line to
  edit.
- **Directories first, then files**, each alphabetically. The convention every
  file manager uses, and here it also keeps the branches at the top of a
  column instead of scattered among the leaves.
- **Nothing is cached, on either side.** Every expansion is a fresh
  `dir_query`. A directory listing stops being true the moment somebody saves
  a file, and a file viewer showing yesterday's directory is worse than a slow
  one. Closing a branch and opening it again re-reads it, which is also the
  only way to refresh one — the cost of the single toggle button, and a cheap
  one.
- **Dotted entries are hidden and counted.** A home directory has dozens
  and they would bury what anybody came looking for on the first click. The
  count goes in the tooltip, because dropping them silently would be lying
  about the machine.
- **Twenty children per expansion, and the cap steps.** A directory with two
  hundred entries would make a column five thousand pixels tall out of one
  click with no way back but to collapse it. Over the cap, the branch grows
  `… N more` and `… previous 20` nodes that move the page under the parent.
- **The tooltip is the folder's name**, and nothing else unless there is
  something to admit: a hidden count, or why the directory could not be read.
- **A drag is a pan, not a click.** Vanilla pans this window by dragging, so
  the expansion fires on release and only if the mouse stayed within three
  pixels of where it went down. Expanding re-rows everything below, so the
  clicked node is held still on screen — otherwise the branch you just opened
  jumps out from under the cursor that opened it.
